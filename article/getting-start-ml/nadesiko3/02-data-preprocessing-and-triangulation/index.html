    第 2 章: データの前処理と三角測量¶

    2.1 はじめに¶

    この章では、機械学習の前に必ず必要になる前処理を実装します。題材はアヤメ（iris）のデータで、150 件の測定値から品種を当てる問題です。第 3 章で決定木を学習させるための土台を作ります。

    この章の山場は乱数生成器を自作することです。なでしこ3 の 乱数 にはシードを渡す口が無く、並びを再現できません。そこで java.util.Random と同じ 48 ビットの線形合同法を書きます。

    ここでなでしこ3 に固有の難しさがあります。数値が float64 だけなのです。Haskell 版は Int が溢れると折り返すので仕様をそのまま書けました。PHP 版は溢れると float に化けるので乗算を分けました。なでしこ3 は最初から float しか無いので、PHP 版よりさらに細かく分けます。

    Python 版の第 2 章 と同じ題材・同じ TODO リストで進めます。

    2.5 乱数生成器を自作する¶

    java.util.Random の仕様¶

    java.util.Random は 48 ビットの状態を持ち、次の式で状態を進めます。

    状態 = (状態 × 0x5DEECE66D + 0xB) を 2^48 で割った余り

    シードからの初期化は (シード XOR 0x5DEECE66D) の下 48 ビットです。整数を 1 つ取り出すときは、状態の上位 31 ビットを使います。

    float64 では 2^53 までしか正確でない¶

    なでしこ3 の数値は IEEE 754 の倍精度浮動小数点数（float64）だけで、整数を正確に表せるのは 2^53 までです。48 ビットの状態に 35 ビットの乗数を掛けると、積は 2^83 に達します。そのまま掛けると下の桁が失われます。

    「{25214903917 × 281474976710655}」を表示

    7.097364492798979e+24

    24 ビットずつに分けて掛ける¶

    状態と乗数をどちらも 24 ビットずつに分けます。

    状態 = 上位 × 2^24 + 下位       （上位・下位はどちらも 24 ビット）
乗数 = 1502 × 2^24 + 15525485   （0x5DE と 0xECE66D）

    展開すると 4 つの積になります。

    状態 × 乗数 = 上位×1502 × 2^48 + (上位×15525485 + 下位×1502) × 2^24 + 下位×15525485

    2^48 の余りを取るので、1 つめの項は丸ごと消えます。 残りの積はどれも 24 ビット × 24 ビット以下なので 2^48 未満に収まり、float64 で誤差なく計算できます。

    二十四ビット = 16777216
乗数上位 = 1502
乗数下位 = 15525485
加数 = 11

●(生成器を)状態前進とは
    上位 = 生成器["上位"]
    下位 = 生成器["下位"]
    下位積 = 下位 × 乗数下位 + 加数

    2.13 まとめ¶

    この章では、アヤメのデータを読み込み、欠損値を補完して、訓練データとテストデータに分けました。なでしこ3 に固有の論点は次のとおりです。

    1. 数値が float64 だけ — 整数を正確に表せるのは 2^53 まで。java.util.Random の 48 ビットの状態に 35 ビットの乗数を掛けるため、状態と乗数を 24 ビットずつに分け、2^48 以上の項を捨てる形に展開した
    2. XOR は 32 ビットの符号付き整数で計算する — 初期化の XOR も 24 ビットずつ行う
    3. Java の「溢れて負になる」判定を書き直す — なでしこ3 の数値は溢れないので、2^31 と比べる
    4. 配列と辞書は参照で渡る — 並べ替えは複製してから行う。生成器は辞書を書き換えて進める
    5. = はゆるい比較 — 0 = 「」 も 「0」 = 0 も真。空欄の判定には型まで比べる === を使う
    6. 組み込みの名前・助詞と衝突する — 合計 は命令の名前、桁上がり は「が」で割られる
    7. 自作のデータと参照実装で突き合わせる — 実データが無くても、同じ形のデータと別の言語で書いた参照実装で、数値を最後の桁まで確かめられる。数行のテストデータでは出ない誤りが見つかった
