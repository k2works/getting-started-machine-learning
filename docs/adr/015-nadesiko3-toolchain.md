# 015 なでしこ3 版の処理系・テスト・静的検査の選定

「機械学習から始めるプログラミング入門」の番外編（Extra）、なでしこ3 版で使う処理系と道具を決める。

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

[執筆計画](../article/getting-start-ml/outline.md) の「Extra: なでしこ3（nadesiko3go）版執筆計画」では、14 言語で完成したシリーズに、日本語プログラミング言語「なでしこ3」の版を番外編として加えるとした。なでしこ3 の公式実装は TypeScript 版で、本シリーズでは Go で書かれた実装 [nadesiko3go](https://github.com/kujirahand/nadesiko3go)（コマンド名 `gonako`）を使う。インストールせずに動く単一のバイナリになり、Go 版と同じ土台の上で読み比べられるためである。

B76 のステップ 1 で、nadesiko3go を手元でビルドし、スクラッチパッドの使い捨てのスクリプトで次を確かめた。

| 確認したこと | 結果 | 確認方法 |
|------------|------|---------|
| 処理系 | nadesiko3go 3.8.8（2026-09-24 のタグ）、MIT License。2026-09-28 にもコミットがあり、活発に保守されている | GitHub のリポジトリ、`gonako version` |
| Go の版 | `go.mod` が `go 1.26.0` を要求する。**flake.lock が固定する nixpkgs の `go` は 1.25.5、`go_1_26` は 1.26rc1 で、どちらも要求を満たさない**。nixpkgs の Go は既定で `GOTOOLCHAIN=local` なので、そのままでは `requires go >= 1.26.0 (running go 1.25.5; GOTOOLCHAIN=local)` で止まる。`GOTOOLCHAIN=go1.26.8` を指定すると 1.26.8 のツールチェーンを取得して入る | Go 1.25.5 で再現 |
| 版の指定 | タグが `v` の付かない `3.8.8` なので Go のモジュールの版として読めず、`@3.8.8` はコミットに解決されて疑似版 `v0.0.0-20260924163730-f840295acd3d` になる | `go install` の出力 |
| テスト | 専用のテスティングフレームワークは無い。`AとBがASSERT等` は失敗すると終了コード 1 で止まる。**最初の失敗で止まるので、ほかのテストの結果が分からない** | 使い捨てのスクリプト |
| エラー | `「…」のエラー発生` で失敗を起こし、`エラー監視` 〜 `エラーならば` 〜 `ここまで` で捕まえられる。捕まえなければ終了コード 1 になる | 同上 |
| 静的検査 | `gonako lint` は関数名の打ち間違いを捕まえる（終了コード 1）。**1 回に 1 ファイルしか受け付けない**。`gonako format` は整形の結果を出力するだけで、検査用のモードが無い | わざと崩したファイル |
| doctest | `gonako doctest` は `.txt` だけを対象にし、**`.md` を渡すと「対象のサンプルコードがありません」で終了コード 0 になる**（黙って成功する） | Markdown とテキストで実行 |
| カバレッジ・型検査 | どちらも無い | `gonako --help` |
| 数値 | float64 だけ。**`「170cm」+0` が `170` になる**（先頭の数字だけ読む）。`「高い」+0` は `NaN` | 使い捨てのスクリプト |
| CSV | `CSV取得` は BOM を取り除かず、空行を「空文字列 1 つだけの行」として読む | BOM 付きのファイルで確認 |
| 乱数 | `乱数` は Go の `rand.Float64()` を呼び、シードを渡す口が無い | `internal/mathlib/mathlib.go` |
| 機械学習・行列 | どちらの命令も無い（行列の命令は転置の `表行列交換` だけ） | `gonako doc` |

### 各章で確かめた結果

| 章 | 確かめたこと |
|----|------------|
| 1 | テスト補助を自作した（`ASSERT等` は最初の失敗で止まる）。**識別子に助詞を入れられない**（`ルールで判定` が「ルール」の定義に割られる）。**lint はかっこの中や値の位置の未定義の名前を素通りさせる**（`undefined` になる）。`!厳チェック` は構文として受け付けるだけ。`「170cm」+0` が 170 になるので正規表現で形を確かめる。書式指定の命令が無いので小数表示を自作した |
| 2 | **24 ビットずつに分けた線形合同法**で、シード 0 の `nextInt(100)` が `[60, 48, 29, 47, 15]`、`[0..9]` の並べ替えが `[4, 8, 9, 6, 3, 5, 2, 1, 7, 0]` になり、Java 版・Elixir 版・PHP 版・Haskell 版と一致した。上位 24 ビットが 0 でないシード（`12345678901`）も Python の参照実装と一致した。`XOR` は 32 ビットの符号付き整数で計算するので初期化も 24 ビットずつ行う。**`=` は JavaScript の `==` と同じゆるい比較で `0 = 「」` が真になる**ため、空欄の判定は `===` にした。辞書はキーを入れた順を保つ。自作のアヤメ風データで、分割と補完前の平均 4 列が Python の参照実装と最後の桁まで一致した |
| 3 | 決定木を辞書で表した。`表数値ソート` は安定（`sort.SliceStable`）で、元の表を書き換える。**引数を `終了` と名付けると、プロセスを終わらせる命令が呼ばれ、エラーも出さず終了コード 0 で止まる**ので、`check.sh` で検査結果報告まで届いたかを確かめるようにした。`の間` の条件はかっこで囲まないと、lint は通るのに実行で「『while』はまだ実行に対応していません。」になる。自作のアヤメ風データで、深さごとの正解率と深さ 2 の木の報告が Python の参照実装と 1 文字も違わず一致した |

実データ（配布データ）での数値は、学習データの無い環境で進めたため、第 1〜3 章ともまだ実測していない。

## 決定

| 用途 | 採用 | バージョン | ライセンス | 初出 |
|------|------|-----------|-----------|------|
| 言語・処理系 | nadesiko3go（`gonako`） | 3.8.8（疑似版 `v0.0.0-20260924163730-f840295acd3d`） | MIT | 第 1 章 |
| 処理系の導入 | Nix の `nadesiko3` 環境の Go（1.25.5）から、`GOTOOLCHAIN=go1.26.8` で `go install` する。入れ先は `apps/nadesiko3/bin/`（コミットしない） | Go 1.26.8 | BSD-3-Clause | 第 1 章（記事での解説は第 5 章） |
| テスト | **自作のテスト補助**（`test/helper.nako3`）。検査の件数と失敗を数え、最後に失敗があれば `エラー発生` で終了コード 1 にする。実データのテストはデータが無ければ保留にする | — | — | 第 1 章 |
| テストの実行 | `tools/check.sh` が `test/*_test.nako3` を 1 つずつ実行し、終了コードを集計する | — | — | 第 1 章 |
| 静的検査 | `gonako lint` を全ファイルに 1 つずつかける | 3.8.8 | MIT | 第 1 章（記事での解説は第 5 章） |
| 整形 | `gonako format` の出力と元のファイルの差分が無いことを確かめる | 3.8.8 | MIT | 第 1 章（記事での解説は第 5 章） |
| カバレッジ・型検査 | **無し**。記事でそのことを扱う | — | — | 第 5 章 |
| CSV | `CSV取得`（BOM と空行は自分で取り除く） | 3.8.8 | MIT | 第 1 章 |
| 乱数 | **`java.util.Random` と同じ線形合同法を自作する**（float64 に収まるよう乗算を分ける） | — | — | 第 2 章 |
| 線形代数・機械学習 | **すべて自作する** | — | — | 第 3 章以降 |
| 直列化 | `JSONエンコード`・`JSONデコード` | 3.8.8 | MIT | 第 8 章 |
| API | **JSON の標準入出力でやりとりするコマンド**（HTTP サーバーの命令が無いため） | — | — | 第 15 章 |

- **処理系は疑似版で固定する。** `@3.8.8` と書いても動くが、解決されるコミットはタグの付け替えで変わりうる。疑似版はコミットのハッシュを含むので変わらない
- **flake.lock は更新しない。** 更新すればほかの 14 環境の Go・GHC・JDK などもまとめて上がり、各言語版の数値や検査の結果が変わりうる。なでしこ3 版の環境だけ `GOTOOLCHAIN` で切り替える
- **テストは `ASSERT等` ではなく自作のテスト補助で書く。** `ASSERT等` は最初の失敗で止まり、残りのテストの結果が分からない。テスト補助は失敗を数えて続け、最後にまとめて報告してから失敗させる。xUnit 系のフレームワークが最初に作ったものを、自分で小さく作ることになる
- **関数名・変数名は日本語にする。** なでしこ3 を選ぶ理由そのものである。関数名は取り込んだファイルをまたいで一意にする（同じ名前が 2 つあると衝突する）
- **記事の検査に `gonako doctest` を使わない。** Markdown を対象にせず、しかも黙って成功する。記事の表示結果は実装の実測値から転記する
- **機械学習のアルゴリズムと線形代数はすべて自作が最終実装になる。** 「ライブラリへの置き換え」の節は「ほかの言語版の数値との突き合わせ」の節に差し替える

### 章ごとの方針

| 章 | 置き換え | 方針 |
|----|---------|------|
| 1〜2 | 無し | CSV の BOM・空行・数値の読み取りを自分で書く。乱数は線形合同法を自作する |
| 3 | **無し** | 自作の決定木が最終実装。ほかの言語版の数値と突き合わせる |
| 4〜6 | 無し | 道具立ての章。疑似版による固定・lint・整形の差分・自作のテスト補助・CI を扱い、カバレッジと型検査が無いことを書く |
| 7 | **無し** | 正規方程式を部分ピボット付きのガウスの消去法で自作する |
| 8〜11 | 無し | 前処理・ロジスティック回帰・ランダムフォレスト・評価指標・交差検証を自作する |
| 12 | 無し | リッジ（正規方程式）とラッソ（座標降下法）を自作する |
| 13 | **無し** | ヤコビ法で固有値分解を自作する |
| 14 | 無し | K-means を自作する |
| 15 | 無し | JSON の標準入出力でやりとりする予測コマンド |

### 検討した代替案

| 代替案 | 採用しなかった理由 |
|--------|------------------|
| 公式の TypeScript 版（`cnako3`） | Node.js が要り、TypeScript 版と同じ実行環境になる。Go で書かれた単一バイナリのほうが Go 版と並べて読める |
| flake.lock を更新して Go 1.26 を得る | ほかの 14 環境にも影響する。しかも固定中の nixpkgs の `go_1_26` は rc 版である |
| Nix の `buildGoModule` で `gonako` をパッケージにする | Go 1.26 が nixpkgs に無い問題は同じで、`vendorHash` の管理が増える |
| `ASSERT等` だけでテストを書く | 最初の失敗で止まる。1 つのファイルに複数のテストを書くと、どれが落ちているかの全体が分からない |
| `gonako doctest` で記事を検査する | Markdown を対象にせず、黙って成功する |
| 識別子を英語にする | なでしこ3 を番外編に選んだ理由（日本語で手順を読ませる）が失われる |

## 影響

- 良い影響: 機械学習の手順が日本語の文として読める。関数名がそのまま用語集になる
- 良い影響: テスト補助・線形代数・乱数を自分で作ることで、ほかの版ではライブラリが隠していた部分が見える
- 悪い影響: **カバレッジも型検査も無い。** テストを章ごとに厚くし、ほかの言語版の数値との突き合わせを受け入れ基準に含めて補う
- 悪い影響: **処理系の導入のたびに Go 1.26.8 のツールチェーンをネットワークから取得する。** Nix の環境だけでは閉じない。CI では Go のモジュールとツールチェーンをキャッシュする
- 悪い影響: 処理系が活発に変わっており、版を上げると書き方が動かなくなる可能性がある。版を上げるときは全章のテストを通してから上げる
