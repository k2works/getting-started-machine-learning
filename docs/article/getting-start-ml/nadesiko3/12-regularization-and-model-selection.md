# 第 12 章: 正則化とモデル選択

## 12.1 はじめに

第 7 章の線形回帰は、訓練データの誤差だけを小さくしました。特徴量が増えて互いに似てくると、係数が極端に大きくなり、訓練データにはよく当たるのに未知のデータには当たらない **過学習** が起きます。

この章では、係数の大きさそのものに罰則を加える **正則化** を扱います。

- **リッジ回帰** — 係数の 2 乗の合計に罰則をかける。係数は 0 に近づくが 0 にはならない
- **ラッソ回帰** — 係数の絶対値の合計に罰則をかける。係数がちょうど 0 になるので、要らない特徴量が分かる

罰則の強さ `alpha` は自分で決める値（ハイパーパラメータ）なので、**検証データ** を用意して選びます。

[Haskell 版の第 12 章](../haskell/12-regularization-and-model-selection.md) は、リッジ回帰の正規方程式を hmatrix にも解かせて自作と突き合わせ（差は 8.0e-15）、ラッソ回帰には突き合わせる相手がいないと書きました。**なでしこ3 版には、リッジ回帰にも突き合わせる相手がいません。** 行列の命令が無いので、正規方程式を解くところから自作です（[ADR 015](../../../adr/015-nadesiko3-toolchain.md)）。

そこで、第 13 章の固有値分解と同じく、答えが満たすべき性質をテストにします。

- `alpha` が 0 のリッジ回帰は、**第 7 章の線形回帰と同じ解** になる
- `alpha` を大きくするほど、**係数のノルムが小さくなる**
- リッジ回帰の解は **Xᵀ (t − X w) = alpha w** を満たす
- ラッソ回帰の解は **軟しきい値の条件（KKT 条件）** を満たす

なでしこ3 版では、次の 3 点に注目してください。

- **性質のテストで両側から挟む。** 2 つの正則化を、それぞれの解が満たす式で確かめます。わざと壊した実装が落ちることも確かめました
- **新しく書いた前処理は外れ値の除去だけ。** 標準化・2 次の項・3 分割は、第 2 章と第 9 章の関数を呼ぶだけで済みます
- **座標降下法は素朴に書いても命令の上限に遠い。** 報告 1 回が約 223 万命令でした。ただし上限の 1 万巡まで回ると、それだけで約 1.5 億命令になります

## 12.2 過学習と正則化

### 係数が大きくなりすぎる

特徴量どうしが強く相関していると、「片方を大きく足して、もう片方を大きく引く」ような解でも訓練データには当てはまってしまいます。係数の絶対値が跳ね上がり、入力がわずかに変わるだけで予測が大きく動くようになります。

### 係数の大きさに罰則を加える

最小二乗法が最小にするのは残差の 2 乗和だけです。

$$\lVert t - Xw \rVert^2$$

正則化はここに項を足します。

- リッジ回帰: $\lVert t - Xw \rVert^2 + \alpha \lVert w \rVert^2$
- ラッソ回帰: $\frac{1}{2} \lVert t - Xw \rVert^2 + \alpha \lVert w \rVert_1$

`alpha` が 0 なら最小二乗法に戻ります。大きくするほど係数は 0 のほうへ押されます。

### リッジ回帰の解き方

リッジ回帰は微分して 0 と置くだけで解けます。

$$(X^\top X + \alpha I) w = X^\top t$$

第 7 章の正規方程式の左辺に、対角の `alpha` を足しただけです。解くところは第 7 章の `連立一次方程式求解`（部分ピボット付きのガウスの消去法）がそのまま使えます。

### ラッソ回帰の解き方

L1 の罰則は原点で折れているので微分できません。行列を解いて終わりにはできず、**係数を 1 つずつ順に動かす** 座標降下法を使います。1 つの係数を動かすときは、ほかを固定して最適な値を求め、そこに **軟しきい値作用素** をかけて 0 に寄せます。

## 12.3 題材とデータ

### Boston.csv

ボストンの住宅価格のデータ（100 件）を使います。第 9 章・第 13 章でも使ったものです。この章で使う列は 4 つに絞ります。

### 過学習が起きやすい状況を作る

3 列だけでは過学習しません。そこで、標準化したあとに **2 次の項** を作ります。3 列から 2 乗と交互作用を足すと 9 列になります。2 次の項は元の列と強く相関するので、正則化の効き目が見える状況になります。

### 訓練・検証・テストの 3 つに分ける

`alpha` を選ぶのにテストデータを使ってしまうと、「テストデータに合わせて選んだ」ことになり、テストが未知のデータの代わりになりません。そこで 3 つに分けます。

- **訓練データ** — モデルを学習する
- **検証データ** — `alpha` を選ぶ
- **テストデータ** — 選び終わったあと、一度だけ測る

## 12.5 リッジ回帰を自作する

### Red: 第 7 章の線形回帰と同じになるテスト

Haskell 版と同じ「答えが分かっているデータ」（切片 1、係数 2 と −3）から始めます。

```nako3

正方正解 = [3, -2, 0]

「alpha が 0 なら第 7 章の線形回帰と同じ切片になる」で(零リッジ["切片"])と(最小二乗["切片"])を0.000000001で近似確認
「alpha が 0 なら第 7 章の線形回帰と同じ係数になる」で(零リッジ["係数一覧"])と(最小二乗["係数一覧"])を0.000000001で近似確認
```

`alpha = 0` なら罰則が消えるので、第 7 章の `線形回帰学習` と同じ答えになるはずです。**すでに動いているものを答えに使える** ので、期待値を手で計算する必要がありません。ここまでは Haskell 版と同じです。

ただし、なでしこ3 版ではこのテストの意味が少し重くなります。Haskell 版には hmatrix という別の解き方があり、「自作の正規方程式が正しい」ことはそちらでも確かめられました。なでしこ3 版では、**第 7 章の線形回帰が、正規方程式の組み立て方の違う唯一の比較相手** です。第 7 章は切片の列（すべて 1 の列）を足した計画行列で解き、この章は平均を引いてから解きます。組み立て方が違う 2 つの式が同じ答えになるので、どちらかの組み立てを間違えれば落ちます。

### 性質でも押さえる

Haskell 版と同じく、切片に罰則がかからないことを確かめます。

```nako3
極リッジ = 正方特徴量と正方正解を二列と100000000でリッジ回帰学習
「切片には罰則がかからないので、強く正則化すると予測は正解の平均に寄る」で(極リッジで正方特徴量を線形回帰予測)と[1 ÷ 3, 1 ÷ 3, 1 ÷ 3]を0.000001で近似確認
```

`alpha` を極端に大きくすると係数は 0 に押し切られ、残るのは切片だけです。**その切片が正解の平均（1/3）になる** ことが、中心化が効いている証拠になります。

突き合わせる相手がいない分、解が満たす式も確かめます。リッジ回帰の目的関数を微分して 0 と置いた式を、並べ替えると次の形になります。

$$X^\top (t - Xw) = \alpha w$$

テストの側に、この式の両辺のずれの最大を求める関数を置きました。

```nako3
        もし、逸脱 > 最大ならば
            最大 = 逸脱
        ここまで
    ここまで
    最大で戻る
ここまで
```

```nako3
小リッジ = 小訓練と小正解を小列名と10でリッジ回帰学習
「リッジ回帰の解は Xᵀ (t − X w) = alpha w を満たす」で(小問題と(小リッジ["係数一覧"])を10で検査用リッジ条件違反)と0を0.000000001で近似確認
「わざとずらした係数はリッジ回帰の式を満たさない」で((小問題と(小リッジ["係数一覧"])を11で検査用リッジ条件違反) > 0.001)と真が一致確認
```

2 本目は、検査の関数そのものが空振りしていないことの確かめです。`alpha` を 11 と偽って渡すと、ずれは 0.001 を超えます（`小問題` などは 12.11 節の自作のデータです）。

最後に、`alpha` を大きくするほど係数の 2 乗の合計の平方根（L2 ノルム）が小さくなることを、候補の 5 つの `alpha` すべてで確かめました。リッジ回帰が小さくするのは L2 ノルムなので、絶対値の合計ではなくこちらで単調性を見ます。

## 12.6 ラッソ回帰を座標降下法で自作する

### 軟しきい値作用素

```nako3
●(値と閾値の)軟閾値算出とは
    もし、値 > 閾値ならば
        値 - 閾値で戻る
    ここまで
    もし、値 < (0 - 閾値)ならば
        値 + 閾値で戻る
    ここまで
    0で戻る
ここまで
```

しきい値の外なら 0 のほうへ縮め、中なら 0 にします。符号を反転した値は、第 13 章と同じく `0 - 式` の形で `(0 - 閾値)` と書きました（`-(式)` は解析エラーになるため）。Haskell 版のテスト 3 本に、しきい値ちょうど（`2と2`・`(0 - 2)と2`）が 0 になるテストを足しました。

### 係数と残差をその場で書き換える

Haskell 版は再代入が書けないので、係数を `Map` に持ち、「係数・残差・いちばん大きな動き」の 3 つを組にして畳み込みで持ち回りました。なでしこ3 版は配列をその場で書き換えられるので、PHP 版に近い 1 つの繰り返しになります。

```nako3

    問題 = 特徴量一覧と正解一覧を列名一覧で正則化問題中心化
    列一覧 = 問題["中心化列一覧"]
    二乗和一覧 = []
    重み一覧 = []
    Jを 0から (列一覧の要素数) - 1まで繰り返す
        二乗和一覧に((列一覧[J])と(列一覧[J])の正則化内積算出)を配列追加
        重み一覧に0を配列追加
    ここまで
    残差一覧 = (問題["中心化正解"])を配列複製
    件数 = 残差一覧の要素数
    周数 = 0
    (周数 < ラッソ反復上限)の間
        最大変化 = 0
        Jを 0から (列一覧の要素数) - 1まで繰り返す

            ここまで
            新値 = ((現列と復元一覧の正則化内積算出)と強度の軟閾値算出) ÷ 二乗和一覧[J]
            残差一覧 = []
            Iを 0から 件数 - 1まで繰り返す
                残差一覧に(復元一覧[I] - 新値 × 現列[I])を配列追加
            ここまで
            重み一覧[J] = 新値
            変化 = (新値 - 旧値)の絶対値
            もし、変化 > 最大変化ならば
                最大変化 = 変化
            ここまで
        ここまで
        周数 = 周数 + 1
        もし、最大変化 < ラッソ収束幅ならば
            抜ける
        ここまで
    ここまで

```

打ち切りの条件・更新の順・軟しきい値のかけ方は、Haskell 版の `lassoFit` にそろえました。

| 項目 | 決め方 |
| :--- | :--- |
| 打ち切り | 1 巡でいちばん大きな係数の動きが `1e-10`（`ラッソ収束幅`）より小さくなったら、その巡の結果で止める。上限は 1 万巡（`ラッソ反復上限`） |
| 更新の順 | 列の順に 1 つずつ。動かした係数はすぐ残差に反映し、次の列はその残差で決める |
| 残差の直し方 | 古い係数の寄与を足し戻した `復元一覧` を作り、新しい係数の寄与を引いて新しい残差にする（差分だけを引く形にはしない） |
| 軟しきい値 | 列と `復元一覧` の内積に、しきい値 `alpha` のままかける（2 で割らない） |

最後の 2 行は、計算の結果を Haskell 版とビット単位でそろえるための選択です。[Go 版](../go/12-regularization-and-model-selection.md) は残差を「新旧の差 × 列」だけ直し、しきい値を `alpha/2` にしています（目的関数の定数倍が違う）。どちらも正しい座標降下法ですが、浮動小数点の丸めが変わり、`alpha` の尺度も変わります。

「書き換わる変数」を組にして持ち回る Haskell 版に比べると、なでしこ3 版は **書き換える変数がそのまま名前で並ぶ** ので、数式との対応は追いやすくなります。その代わり、配列は参照で渡るので、`問題["中心化正解"]` を書き換えないよう、最初に `配列複製` してから残差として使います。

### 名前に使えなかった 2 つの言葉

この関数を書いたとき、文法の検査が次のように止まりました。

```text
[文法エラー]src/chapter12.nako3(135行目): 関数『chapter12__ラッソ回帰学習』の定義で以下のエラーがありました。
[文法エラー]src/chapter12.nako3(135行目): 『ここまで』がありません。関数定義の末尾に必要です。『=』の前に『ここまで』を記述してください。
```

原因は、巡回の回数を数える変数を `巡回` と名付けたことでした。`回` は `3回` のように繰り返しを表す語なので、`巡回 = 0` の `回` が繰り返しとして読まれ、そのあとの `=` の置き場所が無くなったと考えられます。`周数` に変えると通りました。テストの側でも、ずれを表す変数を `違反` と名付けたら「『違』の前に『ここまで』を記述してください」で止まりました。`違えば` の `違` と読まれたようです。`逸脱` に変えています。

どちらも、使い捨てのファイル（関数の中に `巡回 = 0` や `違反 = 0` とだけ書いたもの）で同じエラーになることを確かめました。**エラーは定義の先頭の行を指し、原因の行を指しません。** これまでに見た「助詞やひらがなを名前に入れない」「組み込みの名前と重ねない」に加えて、**`回` や `違` のように構文の語と同じ漢字で始まる、または終わる名前も避けます。**

### KKT 条件をテストにする

両端を挟むだけでは、途中の `alpha` で正しいかは分かりません。Haskell 版はそこを「ほかの言語版と 0 になった 3 列が一致すること」で支えました。なでしこ3 版は、それに加えて **ラッソ回帰の解が満たすべき条件** をテストにします。

勾配を g = Xᵀ (t − X w) とすると、ラッソ回帰の最適な解では、列ごとに次が成り立ちます。

- 係数が正なら g = alpha、負なら g = −alpha
- 係数が 0 なら |g| ≦ alpha

2 つ目が「軟しきい値の中なら 0 にする」に対応します。この条件（KKT 条件）からのずれの最大を求める関数をテストに置きました。

```nako3

    列一覧 = 問題["中心化列一覧"]
    最大 = 0
    Jを 0から (列一覧の要素数) - 1まで繰り返す
        勾配 = (列一覧[J])と残差一覧の正則化内積算出
        逸脱 = (勾配 + 強度)の絶対値
        もし、(重み一覧[J]) > 0ならば
            逸脱 = (勾配 - 強度)の絶対値
        ここまで
        もし、(重み一覧[J]) = 0ならば
            逸脱 = ((勾配)の絶対値) - 強度

            最大 = 逸脱

```

### z スコアで外れ値を除く

第 9 章は四分位範囲で外れ値を判定しました。この章は **z スコア** で、標準偏差は **件数 n − 1 で割る標本標準偏差** を使います（標準化の n とは違います）。

```nako3

```

Haskell 版が書いたとおり、n 件のデータの z スコアには (n − 1) ÷ √n という上限があり、10 件では 2.846 までしか届きません。Haskell 版の 2 本のテスト（20 件なら 1000 が除かれる、10 件なら除かれない）をそのまま書きました。


Haskell 版の 2 本は、標準偏差を n で割っても通ってしまいました（12.6 節の表）。10 件の例では、n で割ったときの上限 √(n − 1) がちょうど 3 で、しきい値を超えないからです。そこで、n − 1 で割れば残り、n で割れば除かれる値を探して、境界のテストを 1 本足しました。


空欄のテストも Haskell 版と同じ形です。Haskell 版は「1 列の CSV では空欄の行が空の行として読み飛ばされる」ことに刺されて列を 2 つにしました。なでしこ3 版の `表読込` も、すべてのセルが空の行を読み飛ばします（第 1 章）。同じ理由で、同じ 2 列の CSV（`v,w{改行}1,1{改行},2{改行}2,3{改行}`）を使っています。

**報告は参照実装と 1 文字も違いませんでした。** 完全な精度の値 37 個（実験表の 15 個、テストデータの決定係数 2 個、`alpha` 10 のリッジ回帰と `alpha` 23.5 のラッソ回帰の切片と係数 20 個）も、参照実装とビット単位で一致しました。乱数の種を変えた自作データをさらに 5 通り作り（除かれる外れ値が 3 件のもの、ラッソ回帰が 0 にする列が 3〜5 列と変わるものを含む）、6 通りすべてで報告も 37 個の値も一致しました。ラッソ回帰の巡回は 51〜118 巡で、上限の 1 万巡には遠く届きませんでした。

これは自作のデータでの値で、実データの値ではありません。

### 命令の数

gonako は 1 回の実行で 2 億命令を超えると止まります（ADR 015）。計測用に作り直した処理系で、自作のボストン風データでの命令の数を測りました。

| 計測 | 命令の数 |
| :--- | :--- |
| `第12章実行` 1 回（読み込みから報告まで） | 約 223 万 |
| うち、ラッソ回帰 1 回（77 巡） | 約 116 万（1 巡あたり約 1.5 万） |
| テストファイル 1 つ（データなし） | 約 111 万 |
| テストファイル 1 つ（自作データを実データの場所に置いたとき） | 約 448 万（乱数の種を変えた別の自作データで約 508 万） |

目安の 1.5 億命令には遠く、第 8・10・14 章のような書き直しは要りませんでした。**ただし、ラッソ回帰が上限の 1 万巡まで回ると、1 巡あたり約 1.5 万命令で、ラッソ回帰だけで約 1.5 億命令になります。** 実データで収束が遅ければ、報告全体が上限に近づきます。自作データで 51〜118 巡だったこと、Haskell 版が同じ打ち切りの条件で 0 になった 3 列をほかの言語版とそろえていることから、実データでも上限には届かないと見込んでいますが、実データでの巡回の数はまだ測っていません。時間は `第12章実行` 1 回が起動を含めて約 0.8 秒でした。

### 結果を読む

期待する出力（ほかの言語版の実測）から読めることは、Haskell 版と同じです。

- `alpha` を大きくするほど、係数の絶対値の合計は 14.187 から 5.684 へ小さくなり、訓練データの決定係数は下がり続けます
- 検証データの決定係数は `alpha = 10.0` で最も高く（0.7349）、`100.0` では訓練・検証とも大きく下がります。正則化が強すぎて学習不足になっています
- 検証データで選んだ `alpha = 10.0` のリッジ回帰は、テストデータの決定係数が 0.6243 で、線形回帰の 0.5224 を上回ります。**訓練データでは線形回帰のほうが高い（0.8827）のに、未知のデータでは正則化したモデルのほうがよく当たっています**
- ラッソ回帰は、9 列のうち `PTRATIO^2`・`PTRATIO LSTAT`・`LSTAT^2` の 3 列の係数をちょうど 0 にします

100 件ほどのデータでは、分け方やデータのわずかな違いで結論まで変わりえます。Haskell 版の 12.11 節は、Kotlin 版で分割の乱数が違ったためにリッジ回帰がテストで線形回帰を下回った例を挙げています。12.10 節の自作データ 6 通りでも、検証データで選ばれた `alpha` は 10.0 が 4 通り、1.0 と 0.0 が 1 通りずつで、選んだリッジ回帰がテストデータで線形回帰を上回ったのは 4 通り、同じ（`alpha` 0 が選ばれた）が 1 通り、下回ったのが 1 通りでした。1 回の分け方に頼らない方法として、第 11 章の交差検証を組み合わせられます。

## 12.14 まとめ

この章では、リッジ回帰とラッソ回帰をなでしこ3 の TDD で自作し、検証データでモデルを選びました。

| 作ったもの | 支え |
| :--- | :--- |
| リッジ回帰 | 第 7 章の線形回帰（`alpha` 0 で一致）、Xᵀ (t − X w) = alpha w、係数のノルムの単調な減少 |
| ラッソ回帰（座標降下法） | 両端のテスト（0 に押し切る・最小二乗法に戻る）、KKT 条件、ほかの言語版が 0 にした 3 列 |
| z スコアによる外れ値の除去 | 性質と上限 (n − 1) ÷ √n のテスト |
| 標準化・2 次の項・3 分割 | 第 2 章・第 9 章の関数をそのまま再利用 |

なでしこ3 版ならではの学びは次のとおりです。

1. **リッジ回帰にも突き合わせる相手がいない** — 代わりに、組み立て方の違う第 7 章の正規方程式と、解が満たす式で確かめた。わざと壊した実装が落ちることも確かめた
2. **ラッソ回帰は KKT 条件で途中を確かめる** — 両端のテストだけでは、途中の `alpha` での正しさは分からない。0 の係数と 0 でない係数の両方があることも確かめて、条件の両方の場合を試した
3. **配列をその場で書き換えられる** — 座標降下法が 1 つの繰り返しで書ける。その代わり、配列は参照で渡るので、残差にする前に複製する
4. **命令の上限には遠いが、上限の巡回数では近づく** — 報告 1 回が約 223 万命令。ラッソ回帰が 1 万巡回ると約 1.5 億命令になる
5. **構文の語と同じ漢字を名前に入れない** — `巡回` と `違反` は変数名に使えなかった
