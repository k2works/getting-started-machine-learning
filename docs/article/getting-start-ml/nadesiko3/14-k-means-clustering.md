# 第 14 章: K-means によるクラスタリング

## 14.1 はじめに

この章の **クラスタリング** は、正解ラベルの無いデータを、似たものどうしのかたまりに分ける教師なし学習です。使うのは **K-means** で、あらかじめクラスタの数 $k$ を決め、「各点を最も近い中心に割り当てる」「クラスタごとの平均を新しい中心にする」を中心が動かなくなるまで繰り返します。

なでしこ3 には K-means のライブラリが無いので、[Haskell 版](../haskell/14-k-means-clustering.md)と同じく **自作したものがそのまま最終実装になります**（[ADR 015](../../../adr/015-nadesiko3-toolchain.md)）。突き合わせる相手は、Haskell 版など `java.util.Random` と同じ乱数で初期中心を選ぶ言語版の数値と、自作のデータで動かす Python の参照実装です。

なでしこ3 版では、次の 3 点に注目してください。

- **gonako は 1 回の実行で 2 億命令を超えると止まる**。Haskell 版と同じ書き方で K-means を書くと、報告を作り終える前に「実行した命令が多すぎます」で止まりました。この章の大半は、命令の数を数えて減らす話です
- **命令を減らしても、結果は 1 ビットも変えない**。距離を測る点を減らす仕組み（Hamerly の方法）を入れたあとも、割り当ては「すべての中心と前から順に比べる」素朴な繰り返しと同じでなければなりません。これを、同点がわざと多くなる格子点のテストで確かめます
- **Go で書かれた命令は 1 回で数えられる**。`表列合計` は 440 行を足しても命令 1 つ分です。足す順が自作の繰り返しと同じであることをソースで確かめてから使います

## 14.2 K-means の仕組み

1. クラスタ数 $k$ を決め、初期中心を $k$ 個選ぶ
2. **割り当て**: 各点を、最も近い中心のクラスタに入れる
3. **更新**: クラスタごとに、属する点の平均を新しい中心にする
4. 中心が動かなくなるまで 2 と 3 を繰り返す

「最も近い」は距離の 2 乗で測ります。K-means は初期中心に依存し、悪い置き方をすると局所解に落ちるので、初期中心を 10 通り試して SSE（各点と所属する中心の距離の 2 乗の合計）が最小のものを採ります。ここまでは [Haskell 版](../haskell/14-k-means-clustering.md)と同じです。

## 14.3 題材とデータ

卸売業者の顧客ごとの年間支出額（`Wholesale.csv`、440 件）を使います。`Channel` と `Region` は区分を表す番号なので除き、残る 6 列（`Fresh`・`Milk`・`Grocery`・`Frozen`・`Detergents_Paper`・`Delicassen`）を、列ごとに平均 0・標準偏差 1（件数で割る標準偏差）にそろえてからクラスタリングします。

振る舞いはすべて Haskell 版にそろえます。

| 項目 | 決めごと |
|------|---------|
| 初期中心 | シード付きの乱数（第 2 章の自作の線形合同法）で点の番号を並べ替え、先頭から $k$ 個 |
| 試す回数 | シードを 0 から 1 ずつずらして 10 通り。SSE が同じなら先に試したほう |
| 打ち切り | 中心がすべての値で変わらなくなるか、更新が 300 回に達したら |
| 同点 | 距離が同じなら番号の小さい中心 |
| 空のクラスタ | 点が 1 つも割り当てられなければ、前の中心を残す |
| 足し算の順 | どれも 0 から始めて前から順に足す |

## 14.14 実データでクラスタリングする

### 2 億命令で止まる

ここまでを Haskell 版と同じ形で書き、実データと同じ形の架空のデータ（440 行・6 列・欠損なし。配布データではない。この節の後半を参照）で報告を作らせると、約 3.2 秒後に止まりました。

```text
[実行時エラー]run14.nako3(35行目): 実行した命令が多すぎます。終わらない繰り返しになっていませんか。
```

処理系のソース（`internal/vm/vm.go`）を読むと、実行の既定の設定に `MaxInstructions: 200_000_000` があり、**1 回の実行で 2 億命令を超えると止まる**作りでした。`gonako --help` にこの上限を変える引数はありません。第 1〜6 章のテスト（学習データの無い環境）は、この上限に当たっていません。

### 命令の数を数える

減らすには、まず数える必要があります。処理系を手元で作り直し、実行の最後に命令の数と関数ごとの内訳を表示するようにしました（計測のためだけの改造で、リポジトリには入れていません）。

最初の書き方（距離も中心の更新もなでしこ3 の繰り返しで書き、毎回すべての点とすべての中心の距離を測る）では、報告に要る 100 回の学習だけで **4 億 7372 万命令**でした。上限の 2.4 倍です。更新の回数は 100 回の学習で合わせて 1566 回で、Python の参照実装と同じでした。

命令の数を小さな計測で分けると、なでしこ3 のどこが高いかが分かります。

| 書き方（6 列の点の距離の 2 乗を 1 回求める） | 命令の数 |
|------|---------|
| `Iを 0から (甲の要素数) - 1まで繰り返す` で 1 列ずつ足す | 81 |
| 同じ繰り返しで `(甲[I] - 乙[I]) ^ 2` と書く | 87 |
| `甲を反復` で `対象` と `乙[対象キー]` を使う | 172 |
| `甲[I + 1]` のように添字を計算して 6 列ずつ展開する | 84 |
| `甲[0]` 〜 `甲[5]` と定数の添字で 6 列を展開する | 42 |
| （参考）`配列合計` で 6 個を足す | 3 |

**繰り返しの制御に、足し算そのものと同じくらいの命令がかかっています。** 添字に計算を入れると、展開しても減りません。そして Go で書かれた命令（`配列合計`・`表列合計`）は、中で何個足しても数命令です。

### 距離を測る点を減らす

命令の大半は距離の計算でした。そこで K-means の結果を変えずに、測る距離の数を減らします。使うのは **Hamerly の方法** です。点ごとに次の 2 つを持ち回ります。

- **上界**: 所属する中心までの距離（2 乗ではない距離）より大きいとわかっている値
- **下界**: ほかのどの中心までの距離よりも小さいとわかっている値

中心が動いたら、三角不等式から、上界には所属する中心が動いた距離を足し、下界からはほかの中心が動いた距離の最大値を引けば、どちらも正しい界のままです。**上界 < 下界 なら、所属する中心がいちばん近いままなので、その点は距離を 1 つも測らずに済みます。** 「上界 < 所属する中心からいちばん近いほかの中心までの距離の半分」でも同じことが言えます。決めきれない点だけ、所属する中心までの距離を測り直し、それでもだめなら探し直します。

```nako3
        Iを 0から 点数 - 1まで繰り返す
            所属 = ラベル一覧[I]
            上界 = 上界基準[I] + 累計移動[所属]
            境界 = 下界基準[I] - 最大移動累計
            もし、半径一覧[所属] > 境界ならば
                境界 = 半径一覧[所属]
            ここまで
            もし、上界 + クラスタ確定幅 × (1 + 上界) < 境界ならば
                続ける
            ここまで
            点 = 点一覧[I]
            所属二乗 = 点と(中心一覧[所属])のクラスタ二乗距離
            上界 = 所属二乗の平方根
            もし、上界 + クラスタ確定幅 × (1 + 上界) < 境界ならば
                上界基準[I] = 上界 - 累計移動[所属]
                続ける
            ここまで
            近傍 = 点と中心一覧を所属と所属二乗と(近隣表[所属])でクラスタ近傍探索
            ラベル一覧[I] = 近傍[0]
            上界基準[I] = 近傍[1] - 累計移動[近傍[0]]
            下界基準[I] = 近傍[2] + 最大移動累計
        ここまで
```

なでしこ3 版ならではの工夫が 2 つあります。

- **界を「累計との差」で持つ**。上界そのものではなく「上界 − その時点の累計移動」を覚えておけば、距離を測らなかった点の値を毎回書き換えずに済みます。書き換えも 1 命令ずつ数えられるからです
- **探し直しは、所属する中心から近い順に比べて打ち切る**。中心ごとにほかの中心を近い順に並べた表（`クラスタ近隣表作成`。並べ替えは安定な `表数値ソート`）を作っておき、`距離(所属, 乙) > 2 × 距離(点, 所属)` になったところで、それより遠い中心は測らずに打ち切ります

```nako3
    打切距離 = 2 × 所属距離 + クラスタ確定幅 × (1 + 所属距離)
    Jを 0から (近隣番号の要素数) - 1まで繰り返す
        もし、近隣距離[J] > 打切距離ならば
            見積 = 近隣距離[J] - 所属距離
            もし、見積 < 下界ならば
                下界 = 見積
            ここまで
            抜ける
        ここまで
        K = 近隣番号[J]
        候補二乗 = 点と(中心一覧[K])のクラスタ二乗距離
        候補 = 候補二乗の平方根
        # 遠い（候補二乗 > 最短二乗）ことがほとんどなので、その比べ方を先にする。
        もし、候補二乗 > 最短二乗ならば
            もし、候補 < 下界ならば
                下界 = 候補
            ここまで
        違えば、もし、(候補二乗 < 最短二乗 または K < 最近)ならば
            もし、最短 < 下界ならば
                下界 = 最短
            ここまで
            最近 = K
            最短二乗 = 候補二乗
            最短 = 候補
        違えば
            もし、候補 < 下界ならば
                下界 = 候補
            ここまで
        ここまで
    ここまで
```

**同点の扱いを変えないこと**が肝心です。比べる順が「前から順」ではなくなったので、`<` だけでは「番号の小さい中心」を選べません。測った中心どうしは距離の 2 乗で比べ、同じなら番号の小さいほうを選びます。測らずに飛ばすのは、距離が **確かに大きい** 中心だけです。

「確かに」のために、`クラスタ確定幅`（1e-9）の幅を取っています。上界と下界は平方根と足し引きを重ねた浮動小数点数なので、ほぼ同じ距離のところで丸めの誤差が大小を逆転させるかもしれません。幅の内側では「決めきれない」として距離を測り直すので、割り当てを決めるのは常に、測った距離の 2 乗どうしの比べ合いです。

このテストが空振りしていないことは、壊して確かめました。同点で番号の小さい中心を選ぶ条件を消すと、比べた 48 通りの一部が不一致になり、幅を負の値にして「確かに」を崩しても不一致になります。

## 14.18 まとめ

この章では、K-means をなでしこ3 で自作しました。なでしこ3 に固有の論点は次のとおりです。

1. **gonako は 1 回の実行で 2 億命令を超えると止まる** — 処理系の既定の設定で、コマンドから変える引数は無い。素朴な K-means は報告に 4.7 億命令を要した
2. **命令を数えてから減らす** — 処理系に命令の数と関数ごとの内訳を表示させて測った。繰り返しの制御は足し算と同じくらい高く、Go で書かれた命令は中で何個足しても数命令
3. **結果を変えずに距離を測る点を減らす** — Hamerly の方法で、距離の上界と下界から「所属が変わらない」とわかる点を飛ばした。界は累計との差で持ち、探し直しは近い順に比べて打ち切る。1.4 億命令になった
4. **同点の扱いを守る** — 比べる順が変わっても、距離の 2 乗が同じなら番号の小さい中心を選ぶ。飛ばすのは幅（1e-9）を取って「確かに遠い」中心だけ
5. **速い書き方は素朴な書き方でテストする** — 同点や空のクラスタが起きやすい格子点で、ラベル・中心・SSE・反復回数を丸ごと比べる
6. **`表列合計` は 0 から前の行へ順に足す** — ソースで確かめてから使い、中心の値を最後の桁まで保った
7. **`二乗` は組み込みの命令** — 変数名にすると「関数『二乗』に代入できません」になる
